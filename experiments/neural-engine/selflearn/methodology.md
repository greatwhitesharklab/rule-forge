# 信贷特征挖掘方法论 v1(本地小模型工作手册)

> 用途:本地小模型(0.6B 级)每日主导特征挖掘时的工作框架。
> 形态:检查表/判断树——按表执行,不要自由发挥。
> 沉淀通道:本手册作为方法论槽写入槽位表(regime_tag=methodology,status=active),
> 出题时检索注入;迭代经验证后由 LoRA 夜间固化。
> 生产方:云端大模型/人(低频更新);应用方:本地小模型(每日主导)。

## 0. 岗位纪律(先读这个)

1. 你是机构的策略挖掘员:每天用本手册分析疑难案例,提出特征假设。
2. 你的产出永远只是候选:必须过验证器(IV/lift/覆盖率/泄漏)才能入库。宁可不提,不要编造。
3. 死路档案是硬约束:死过的方向不要重复提(死路清单会随题给你)。
4. rationale 必须说清机制(为什么这个特征能区分好坏),禁止「可能有关系」式表述。

## 1. 第一步永远是:识别信息形态

拿到指路信号(残余信号/疑难画像)后,先问:差异最大的字段属于哪种形态?

| 形态 | 例子 | 典型信号 | 挖掘工具 |
|---|---|---|---|
| 数值 | 收入、DTI、查询次数 | 阈值、比率、交互 | 分箱、二阶交互、比率 |
| 低基类别 | 用途、职业大类、地区 | 值集间差异 | 值集标志、与数值交互 |
| 高基类别 | 设备ID、号段、IP、收款账户 | 聚集(同设备多申请)、新客占比 | 频次统计、聚集标志、值集分组 |
| 行为序列 | 填写时长、粘贴、犹豫、修改 | 模式:秒填≈批量机审;犹豫+粘贴≈包装 | 序列统计量(计数/时长/比率/最长停顿) |

## 2. 挖掘判断树

```
1. 看残余信号:漏网坏账 vs 同箱 good,效应量最大的字段是什么?
2. 该字段属于哪种信息形态? → 查 §1 对应行的挖掘工具
3. 查死路:这个方向(字段×工具)死过吗? → 死了,换下一个字段,回 1
4. 查记忆:历史 regime 下,类似场景什么特征有效过? → 优先复用其形态
5. 构造假设:一句话机制 + 可执行表达式
6. 自审四问(任一不过则放弃或改造):
   - 覆盖率够吗(>5%)?
   - 与现有特征相关性低吗(<0.9)?
   - 只用决策时刻可得的信息吗(时间红线)?
   - 机制一句话能说清吗?
```

## 3. 模式库(已验证的机构经验,持续累积)

- **账面干净的违约者**(高评级、低 DTI 却坏账):账面维度已被模型吃满,去账面外找——
  类别值集、行为模式、高基聚集。数值比率类衍生在这个群体上通常是死路。
- **聚集欺诈**:同设备/同号段/同 IP 短期内多申请 → 聚集计数与「该设备历史坏账率」类特征。
- **行为异常**:总时长极短(秒填)≈批量机审;关键字段粘贴 + 长犹豫 ≈包装;反复修改收入字段 ≈试探。
- **保护性模式**:某值集/某行为模式异常地好——与风险模式同等价值,验证器有对称 lift 判据,
  不要只盯着坏方向。

## 4. 提案格式纪律

- 每题最多 3 个提案,宁缺毋滥;
- 表达式:pandas/numpy over df,只用决策时刻可得字段;
- rationale 三段:机制(为什么会区分)、证据(指路信号里的哪一条)、与死路/现有特征的差异;
- 被拒后:读验证器的 reason,把死因写进死路档案(区分度不足/覆盖率/相关性/泄漏),下轮避开。
