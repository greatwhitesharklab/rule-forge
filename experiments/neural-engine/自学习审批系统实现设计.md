- **日间（在线）**：审批辅助、云端调用（只读记忆，不写）；

## 1. 本地模型设计

### 1.1 本地模型选型（分两代登场，LLM 不是第一天就需要）

**核心认知**：本地侧的流程骨架（槽位表、声誉、验证、检索）全是普通程序，不需要 LLM。
本地 LLM 只为三件事存在——① 读懂非结构化文本、② 生成假设/归纳经验（Scribe）、
③ 充当 LoRA 慢记忆的载体（θ 通道本体）。写提示词是它变聪明后的顺手应用，不是存在理由。

| 阶段 | 本地配置 | 职责 |
|---|---|---|
| P0~P1 | **encoder（Qwen3-Embedding-0.6B 级）+ GBDT + 模板引擎** | 检索向量、结构化打分、G1 提示词填充；无生成式 LLM |
| P2 起 | **本地 LLM：Qwen3-0.6B**（bf16 ~1.2GB，CPU 可推理，单卡微调无压力） | 文本理解推理、Scribe 归纳、LoRA 巩固载体、G2 提示词策略 |

**为什么 0.6B 起步**：本地 LLM 的职责是"懂机构"而非"懂世界"——通用智能由云端补。
0.6B 的抽象容量对机构级经验（10⁵~10⁷ 槽位蒸馏）足够，且小容量本身就是抽象压力
（学不了个案细节，被迫学规律）；LoRA 微调成本极低（rank 16 可训练参数 <10M）。
若 P2 实测文本理解/Scribe 质量不足，再升到 1.7B/4B，接口不变。

**后续演进**：MoE 版（总参数 3B~8B、激活 <1B）待数据飞轮验证后迁移，路由器必须冻结。

### 1.2 可写 Engram 槽位表（P1 独立服务，P2 焊入 LLM）

**分期策略**：P1 先把槽位表作为独立检索+记账服务跑通（不触碰任何模型内部），
P2 本地 LLM 登场后再焊入其浅层做门控注入。这样数据飞轮第一天就能转，模型手术不影响业务。

槽位 schema（SQLite 存元数据，向量用 numpy/FAISS 存）：

```sql
CREATE TABLE slots (
  slot_id      INTEGER PRIMARY KEY,
  key_vec      BLOB,        -- float32[256] 语义键（检索用）
  value_text   TEXT,        -- 人类可读的经验陈述（审计用）
  value_vec    BLOB,        -- float32[1024] 内容向量（注入/检索用）
  beta_a       REAL,        -- 声誉：成功计数
  beta_b       REAL,        -- 声誉：失败计数
  status       TEXT,        -- candidate/shadow/active/cooling/retired
  regime_tag   TEXT,        -- 所属宏观时期标签
  created_at   TEXT, last_used_at TEXT,
  use_count    INTEGER DEFAULT 0,
  provenance   TEXT         -- JSON: 来源案例ID列表
);
```

**读路径（在线，只读）**：

```python
def retrieve(case_embedding, h_context=None):
    cands = faiss_index.search(case_embedding, k=8)      # 细寻址（MVP 用 FAISS 即可）
    out = []
    for s in cands:
        a_sem = cosine(case_embedding, s.key_vec)         # 语义对齐
        a_rep = s.beta_a / (s.beta_a + s.beta_b)          # 结局声誉
        a_tmp = drift_factor(s)                           # 时间一致性（MVP 可用近期命中率滑动窗口）
        alpha = a_sem * (a_rep ** BETA) * (a_tmp ** GAMMA)
        if alpha > THETA:
            out.append((s, alpha))
            log_attribution(case_id, s.slot_id, a_sem, a_rep, a_tmp)  # 归因日志！
    return out
```

**写路径（夜间，批量）**——三操作，禁止覆盖式更新：
- `reinforce`：新案例与现有槽相似度 > 0.85 → EMA 更新 value_vec（α=0.1），追加 provenance；
- `allocate`：无相似槽 → 新槽（status=candidate，Beta 从 (1,1) 先验起步）；
- `compete`：相似但结局冲突 → 新建竞争槽，并存由声誉仲裁。

**声誉更新（结局回流时）**：

```python
def credit_assignment(case_id, outcome):          # outcome ∈ {good, bad}
    for (slot_id, alpha, _, _, _) in attribution_log[case_id]:
        w = amount_weight(case_id)                # 按敞口加权
        if outcome == 'good': slots[slot_id].beta_a += w * alpha
        else:                 slots[slot_id].beta_b += w * alpha
```

### 1.3 提示词策略模块（本地出题）

分两代实现，**不许跳过 G1**：

**G1：模板 + 槽位填充（规则策略）**
```python
PROMPT_TEMPLATES = {
  "feature_proposal": FEATURE_TEMPLATE,   # 见 §3.2
  "case_analysis":    ANALYSIS_TEMPLATE,
  "explanation":      EXPLAIN_TEMPLATE,
}
def make_prompt(task_type, payload):
    slots = retrieve(payload.embedding)                    # 注入相关经验（摘要形式）
    dead  = dead_end_lookup(payload)                       # 附死路清单
    return sanitize(TEMPLATE.render(payload, slots, dead)) # 脱敏后出站
```

**G2：RL 学习的策略（P3 阶段）**
- 状态：任务类型 + 案例画像 + 历史成功率；
- 动作：模板选择 + 关键参数（案例数、约束条数、输出格式要求）；
- 奖励：验证器给出的结果质量分 Q − λ·云端成本；
- 算法：GRPO 或简单 contextual bandit 起步。

### 1.5 协调者定位：骨架/判断点分离 + 四通道输入

**铁律：流程归代码，判断归模型。**
编排逻辑（夜间巩固流程、何时问云、晋升门评审）是确定性 workflow 代码，可预测、可审计；
本地 LLM 只坐在代码写不出规则的"判断点"上（疑难案例识别、假设表述、语义级验收）。
每个判断点必须有显式的输入输出契约（JSON schema），模型换代（0.6B→1.7B→MoE）时
骨架一行不动，只换判断点背后的模型。禁止把系统写成"大模型全自动 agent"。

**四通道输入：语言是外交语，向量是母语。**
transformer 残差流的原生输入是向量而非文字，各模态各自配编码器直接注入：

```
结构化字段 → GBDT 叶子指纹向量（几百棵树的叶子编号 → embedding）─┐
行为序列   → 事件编码器（事件当 token，序列入向量）              ─┤
文字材料   → 传统分词嵌入                                        ─┼→ 同一残差流
经验记忆   → Engram 检索注入（第四通道，与前三者平级）            ─┘
```

介质使用边界：机器内部能向量就向量（零损耗）；→云 API 必须语言（接口约束）；
→人/监管/审计必须语言（法律接口）；经验条目跨时间传承必须保留 value_text（双国籍）。

### 2.2 出站脱敏（合规红线）

```python
def sanitize(payload) -> payload:
    1. 去除所有 PII：姓名/证件号/手机号/银行卡号/精确地址（正则 + NER 双保险）
    2. 数值泛化：金额→区间码，日期→相对天数，坐标→城市级
    3. 结构保留：统计画像、比率、分布特征原样保留（云端需要的是结构不是身份）
    4. 自动校验：出站包过一遍 PII 扫描器，命中即阻断并告警
```

## 3. 验证器（本地验收，系统的免疫系统）

### 3.1 三类验证

| 云端产出 | 验证方式 | 通过标准 |
|---|---|---|
| 特征表达式（代码） | 沙箱执行（RestrictedPython/容器）→ 历史数据回测 | 语法可跑；IV > 0.1 或 lift > 1.3；覆盖率 > 5%；**泄漏检测**（相关性强得离谱→隔离审查） |
| 案例分析 | 与结局标签对表 | 结论方向与结局一致的占比 > 阈值 |
| 解释文本 | 规则检查（引用特征必须真实存在、无虚构字段）+ 抽检 | 合规词表 + 事实一致性 |

验证结果一律回写声誉系统：该次产出质量分 Q ∈ [0,1] → 记入"云端按任务类型的靠谱率账本"。

### 3.2 沙箱要求

云端代码执行必须：无网络、只读数据视图、30s 超时、内存上限 512MB、禁用 import 白名单外模块。

### 3.3 行为事件数据使用规范

App 点击/停留/表单轨迹等事件流是"第三种语言"，四种用法按价值排序：
1. **聚合进 GBDT**（P1 即做）：申请前 N 天打开次数、停留时长、字段犹豫时长、
   粘贴检测（收入字段手输 vs 粘贴是强欺诈信号）；
2. **事件序列编码**（P1 末-P2）：事件当 token 编码入向量，进检索/Engram 键/残差流；
3. **结局早期信号**：放款后行为（不再打开 App 等）不用于决策，但比 D+30 逾期更早，
   进信用分配环节给声誉更新提供早期标签；
4. **探索矿脉**（P3）：行为序列画像作为特征假设的出题素材。

两条红线：**时间红线**——决策只能用决策时刻之前的行为；
**隐私红线**——出站只许聚合统计形式，必须过 §2.2 脱敏管线。

## 5. 分期实现计划与验收标准

### P0：地基（第 1~2 周）
- 槽位表（SQLite+FAISS）CRUD、三操作写路径、声誉更新、归因日志；
- 云端适配层（至少 1 家 provider 跑通）+ 脱敏模块 + 成本账本；
- 合成信贷世界生成器（CLAB-lite）：8 因子 → 6 概念 → 20 条经验池规则 + 10 条保留池规则，regime 切换（Geo(0.1)），结局延迟 1~3 episode 回流。
- **验收**：单元测试覆盖三操作与声誉更新；生成器产出 10 万案例且规则可复现（固定种子）。

### P1：记忆闭环（第 3~4 周）
- 接入 encoder（Qwen3-Embedding-0.6B 级，出检索向量）与 GBDT 打分基线；
- 夜间巩固全流程跑通（不含 LoRA）；G1 提示词模板 ×3；验证器 ×3；
- **验收**：在合成世界上跑 100 episode，产出四条曲线——股息曲线 N(n)、组合零样本 ZS(t)、损伤保留率 L(t)、声誉收敛曲线；系统 vs 纯 RAG 对照，ZS(t) 显著更高为 PASS。

### P2：本地 LLM 登场 + 焊入（第 5~7 周）
- 引入 Qwen3-0.6B：接管文本理解推理、Scribe 经验归纳（encoder 吃不下的语义活）；
- Engram 门控注入层焊入该模型浅层（零初始化验证：注入前模型输出与基线逐位一致）；
- LoRA 巩固通道 + champion-challenger（rank 16，可训练参数 <10M，单卡/高端 CPU 可训）；
- **验收**：门 α 分布合理（相关语境 >0.7，无关 <0.2）；LoRA 晋升后回放集提升显著且不降旧规则留存率（NT < 5%）。

### P3：策略学习（第 8~10 周）
- G2 提示词策略（bandit 起步）；死路档案驱动的勘探策略；特征状态机全量上线；
- **验收**：提示词成功率随时间上升（前后 50 次任务对比）；死路命中率 > 0（证明勘探在去重）；端到端特征循环产出 ≥3 个过晋升门的特征。

## 6. 技术栈清单

- 模型：PyTorch + transformers + PEFT（LoRA）；P0-P1 仅需 sentence-transformers（encoder）+ LightGBM，无需 GPU；
- 记忆：SQLite（元数据）+ FAISS（向量）+ parquet（案例库）；
- 云端：openai python sdk（兼容协议）+ tenacity（重试）；
- 验证：RestrictedPython 或 docker 沙箱 + pandas/numpy 回测；
- 实验：合成世界生成器独立包，可单测；
- 全程固定随机种子，所有产出带 provenance。

## 7. 风险与注意

1. P1 阶段槽位检索就是"增强版 RAG"，勿自满——P2 焊入层才是 θ 通道；
2. 云端产出**永远只是候选**，无验证不入库，这是铁律；
3. 脱敏是出站唯一通道，任何绕过 sanitize 的调用视为严重 bug；
4. 所有写操作留 WAL：任何时刻的记忆状态可重建（监管复现要求）；
5. 冷启动用行为克隆（历史规则引擎决策）+ 人工模板，不追求首日智能。

## 8. 特征工程体系（v1.1 新增）

### 8.1 特征四层结构

```
L0 原始字段    数据源直出（收入、负债比、事件流……）
L1 规则衍生    人写的确定性表达式（收入/月还款、近30天流水方差……）
L2 摸索衍生    机器假设+验证通过的表达式（探索循环产出）
L3 表征衍生    学出来的隐式特征（GBDT叶子指纹、encoder向量、Engram经验分）
```

L1/L2 是显式特征（可执行、人可读、监管可查，GBDT 吃）；L3 是隐式特征（向量，机器消化，
残差流和检索系统吃）。每个 L2 特征必须同时具备表达式（审计国籍）与效果统计（决策国籍）。

### 8.2 统一流水线（人机同构）

无论特征由人写还是机器写，走同一条流水线：
**定义 → 注册 → 计算 → 验证 → 入库 → 服役 → 体检 → 退役。**

定义形式（可执行 + 有假设陈述 + 有作者版本）：

```python
@feature(name="flow_cv_30d", version="1.2", author="llm_proposal#20260718")
def flow_cv_30d(flow_df):
    """近30天流水变异系数。假设：收入不稳定者违约率高"""
    return flow_df.rolling(30).std() / flow_df.rolling(30).mean()
```

### 8.3 两条工程铁律（信贷特征头号事故源）

1. **线上线下一致性**：训练与推理必须调用同一份特征计算代码（统一特征服务），
   禁止离线 pandas / 线上 SQL 两套实现；
2. **时点正确性（as-of）**：任何窗口统计带时点参数，只用决策时刻之前的数据；
   回测框架强制检查，"特征穿越"是回测虚高的最大来源，也是泄漏检测头号嫌犯。

### 8.4 入库门槛与总量控制

```
入库门槛：IV > 0.1（或 lift > 1.3）；覆盖率 > 5%；跨 regime PSI < 0.25；
          与现有特征相关性 < 0.9（增量价值）；泄漏检测通过
总量控制：入库门槛随库容收紧（边际准入）；现役库容上限（如 ≤800），
          每月体检末位淘汰；退役必须记死因进死路档案
死路档案：死因四类——区分度不足 / regime 不稳 / 覆盖率萎缩 / 被更优替代；
          死因是下一轮假设生成的约束条件（探索效率随时间上升的关键）
```

### 8.5 自动探索循环（各器官位置）

```
① GBDT 指路：特征重要性漂移 + "解释不了的坏账"清单
② 本地 LLM 出题：读疑难案例 → 假设方向 → 查死路档案去重 → 脱敏
③ 云端构造：写成可执行表达式
④ 验证器把关：沙箱 + 时点检查 + 回测 + §8.4 门槛（健康淘汰率 ~70%）
⑤ 影子服役：≥1 个还款周期，只记录不影响决策
⑥ 晋升门 → L2 现役（GBDT 下次重训吃入）
⑦ 月度体检：PSI + 声誉折旧 + 覆盖率 → 退役入死路档案
```

人机分工：GBDT 指路、本地 LLM 出题、云端构造、验证器把关、
**人只出现在晋升门终审与死路档案复盘**——人不写特征了，人审特征。

### 8.6 云端参与编写流水线基础设施

云端不仅写单个特征表达式，也可编写特征基础设施（窗口计算框架、as-of 连接器等）。
分级验证：

| 云端产出 | 性质 | 验证级别 |
|---|---|---|
| 单个特征表达式 | 耗材级 | 全自动（沙箱+回测+泄漏检测） |
| 基础设施代码 | 资产级 | 自动测试 + 人工/实现 agent 评审 + 版本化 + 灰度上线 |

约束：云端只接触 schema 与规范，**不接触真实数据**；代码须通过测试套件
（正确性、时点一致性、性能基准）方可合入。云端=外包程序员，本地=code reviewer，
与"云端产出永远只是候选"的铁律同构。

### 8.7 GBDT 与表格 NN 的竞技场

GBDT 是现役 champion 的理由：阈值/交互形状合身、单调性约束（监管刚需）免费、
特征重要性自带审计、CPU 分钟级重训。但不是铁饭碗：
**每月 TabPFN/FT-Transformer 作为 challenger 与 GBDT 同回放集对比，稳定胜出即换岗。**
全系统每一层（决策/记忆/特征/模型）都是 champion-challenger 竞技场，
唯一不竞争的是规则本身。
